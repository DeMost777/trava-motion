## Насколько это сложно
| Часть | Сложность | Почему |
|---|---|---|
| Лучи слева направо | **низкая** | приём `ambientFlow` уже есть (Client Interaction), роль `m-impulse` уже стоит. Нужно только выбрать линии `bg line` как дорожки |
| Иконки по очереди | **низкая** | приём `pulse` уже есть (CI: 1 → 1.08 → 1). Нужно назвать 5 слоёв `m-node` и выбрать порядок |
| Полоса loading | **низкая–средняя** | заливка растёт слева направо, ползунок едет за ней. Нужны роли `m-progress` (заливка) и `m-knob` (ползунок), новый приём `progress`. Риск: если заливка в SVG окажется контуром, а не прямоугольником, придётся растягивать через clip |
| Число 0 → 12.380 | **средняя–высокая** | Figma при экспорте превращает текст в контуры. В SVG будут только цифры `1 2 . 3 8 0`, а для счёта нужны все десять. Варианты — вопрос 3 |
| Размер кода | мелочь | ≈ +3–4 КБ в сжатой сборке (сейчас 20 КБ, предел ≈ 50 КБ) |

Итог: лучи и иконки — быстрая часть и почти без новых решений. Реальный вопрос — число.

## Вопросы к команде ✋ (рекомендация — первой)
1. **Объём.** (А) лучи + иконки + полоса + число; (Б) сначала лучи + иконки + полоса, число отдельным шагом после проверки; (В) только лучи + иконки. Рекомендую **Б**: основа готова быстро, число не задерживает.
2. **Иконки.** Порядок по часовой от верхней левой: статистика → почта → пользователи → XML → пользователь с письмом; шаг 0.7 с, пульс как в Client Interaction (1 → 1.08 → 1, токены те же). Так оставляем?
3. **Число.** Как считать (текст в SVG — контуры):
   - (а) **рекомендую:** в рабочей копии Figma добавить под карточку (закрыто `Bg`, не видно) текст `0123456789` тем же стилем, что `Number`. Код рисует число готовыми цифрами из Figma — шрифт и вид как в макете. Это добавка слоя, вид иллюстрации не меняется;
   - (б) настоящий текст `<text>` со шрифтом сайта: проще, но вид может отличаться от Figma (шрифт, сглаживание);
   - (в) без счёта: число остаётся 12.380, едет только полоса.
4. **Центр.** 4 коротких штриха у карточки (`bg image`) оставляем неподвижными? Предлагаю да: на них нет запроса, а один из них вертикальный (нужна доработка приёма).
5. **Полоса и цикл.** Предлагаю: конечное состояние = макет (заливка 51 из 123 px, число 12.380). Цикл: заливка и число растут от 0 до макета (≈ 2.5 с), пауза ≈ 1.5 с, мягко назад к 0 и заново. В макете, при reduced motion и при уходе с экрана остаётся готовое состояние. Либо заливка идёт до конца дорожки (123 px), тогда макет и конечное состояние не совпадут. Какой вариант?
6. **Формат числа.** В макете «12.380» (с точкой), в чате «12 380». Оставляем как в макете («Figma — источник правды»)?
7. **Лупа и столбики** (`Statistic`, `Icon`) не трогаем?
