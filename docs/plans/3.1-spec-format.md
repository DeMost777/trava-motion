# 3.1 — формат Motion Specification: варианты

**Статус:** ✅ выбран вариант А (2026-10-07) → [ADR 0016](../decisions/0016-motion-spec-format.md); spec Queue Manager — на утверждении · **Задача:** 3.1 · Решение — в ADR 0016.

## Что уже решено
- Файл `animations/<name>/motion.yaml`, на английском (ADR 0002, ADR 0015). Человеку при утверждении показывается
  пересказ на русском.
- Значения — только из токенов (`tokens/motion.tokens.json`), слои — только роли из `figma.json` (`data-m`).
- Spec читают: агент-разработчик (Builder, фаза 6/8), валидатор (3.3), человек (через пересказ).

## Главный вопрос: на каком уровне описывать движение
Пример — один и тот же кусок Queue Manager (поток импульсов + реакция gear) в трёх вариантах.

### А. Сцены и приёмы (primitives) ✔ рекомендую
Spec говорит, **что** происходит, языком сценария и приёмов движения из аудита 1.1 (`impulseFlow`, `hubAccent`…).
Как это сделать в GSAP — забота primitive (фаза 5).
```yaml
scenes:
  - id: flow
    intent: Passenger impulses stream into the hub from all sides, one after another, without pauses.
    primitive: impulseFlow
    targets: impulse            # role from figma.json
    params:
      direction: toward-hub
      segmentTime: 1.2s
      perSegment: 1
      ease: motion.ease.flow    # token
      start: fill-from-edges
  - id: gear-reaction
    intent: The gear turns and zooms when the stream reaches the hub, then every 3 s.
    primitive: hubAccent
    targets: gear
    params:
      rotate: 360
      zoom: 1.2
      duration: 1.3s
      ease: motion.ease.standard
      every: 3s
      firstAt: after flow reaches hub
```
Плюсы: короткий, читается почти как сценарий; одни и те же приёмы переиспользуются в 8 иллюстрациях; правка
по фидбеку — поменять параметр, а не код. Минусы: нужен словарь primitives (он есть черновиком в аудите 1.1, утвердим в 5.1).

### Б. Таймлайн (почти GSAP)
Spec перечисляет каждый твин: кто, что меняет, когда, сколько.
```yaml
timeline:
  - { target: impulse, from: { x: -50 }, to: { x: 50 }, at: 0, duration: 1.2s, ease: none, repeat: -1, stagger: 1.2 }
  - { target: gear, to: { rotation: 360, scale: 1.2 }, at: 3.44s, duration: 1.3s, ease: power1.inOut, repeat: -1, repeatDelay: 1.7 }
```
Плюсы: точно, без «магии». Минусы: человек бриф в этом не узнает; геометрия и направления (зеркальные импульсы)
утекают в spec; каждая иллюстрация пишется с нуля.

### В. Только текст сценария + параметры темпа
Как `storyboard.md`, но на английском, плюс таблица значений.
Плюсы: проще всего написать. Минусы: валидатор (3.3) почти ничего не проверит; агент каждый раз сам решает,
как воплощать — результат будет разным от раза к разу.

## Поля spec (для варианта А, черновик)
| Поле | Что | Проверяет валидатор (3.3) |
|---|---|---|
| `animation` | имя пакета | совпадает с папкой |
| `story` | смысл одной фразой (из брифа) | не пусто |
| `trigger` | когда запускается: viewport/активная карточка, порог | значения из токенов |
| `loop` | бесконечно / раз; основание (ADR 0007) | если бесконечно — ссылка на ADR |
| `staticState` | что видно при reduced motion и ошибке | = макет |
| `scenes[]` | `id`, `intent`, `primitive`, `targets`, `params` | primitive из словаря; targets из `figma.json`; ease/длительности — токены или явные значения из утверждённого сценария |
| `interrupt` | что при уходе со слайда | по принципам — мгновенно в макет |
| `mobile` | упрощения для телефона | — |
