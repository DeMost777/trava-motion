# 2.5 — стандарт пакета анимации: варианты

**Статус:** ✋ ждёт решения · **Задача:** 2.5 · Решение запишем в ADR 0015.

Что уже есть в `animations/queue-manager/`: `brief.md`, `storyboard.md`, `source/figma-export.svg`,
`source/figma-reference@1x.png`, `illustration.svg`. Дальше добавятся spec (фаза 3), код анимации (фаза 8), результаты QA (фаза 9).

## Решение 1. Раскладка папки

**А. Плоско + `source/` для сырья из Figma** ✔ рекомендую
```
animations/queue-manager/
  README.md            статус пакета и команды (RU, коротко)
  brief.md             бриф человека (RU)
  storyboard.md        сценарий (RU)
  figma.json           паспорт: откуда из Figma, какие слои нужны, хэши (EN, для инструментов)
  source/
    figma-export.svg   сырой экспорт — не редактируется
    figma-reference@1x.png  эталон из Figma
  illustration.svg     подготовленный SVG (делает tools/prepare-svg.mjs)
  motion.yaml          spec для агента (EN) — фаза 3
  animation.js         код — фаза 8
```
Плюсы: всё про иллюстрацию в одном месте, пути короткие. Минус: рукописное и сгенерированное лежат рядом.

**Б. Папки по шагам pipeline** — `1-brief/`, `2-design/`, `3-spec/`, `4-build/`. Наглядно повторяет флоу,
но глубже вложенность и длиннее пути; шаги часто возвращаются назад (как сейчас со сценарием).

**В. Рукописное отдельно от сгенерированного** — `animations/<name>/` (бриф, сценарий, spec, исходники) +
`build/<name>/` (illustration.svg, собранный код). Чисто, но иллюстрация «живёт» в двух местах.

## Решение 2. Где хранить «паспорт» (ожидаемые слои, узел Figma, хэши)

**А. `figma.json` в пакете** ✔ рекомендую
```json
{
  "figma": { "fileKey": "9EMDUpk6j30cPIIzRENFQh", "node": "732:12579", "name": "Queue Manager" },
  "roles": { "impulse": 24, "hub": 1, "gear": 1 },
  "export": { "file": "source/figma-export.svg", "sha256": "…", "exportedAt": "2026-10-07" },
  "reference": { "file": "source/figma-reference@1x.png", "sha256": "…" }
}
```
Инструмент читает его сам: `node tools/prepare-svg.mjs animations/queue-manager` — без длинной командной строки.
Хэши показывают, что исходник не меняли и эталон соответствует экспорту.

**Б. В spec (`motion.yaml`)** — роли и так понадобятся в spec. Но spec — фаза 3, формат ещё не утверждён.
**В. В `storyboard.md`** — человеку видно, но инструменту читать таблицу из текста ненадёжно.

## Решение 3. Хранить ли подготовленный `illustration.svg` в репозитории

**А. Да** ✔ рекомендую — в git видно, что изменилось после нового экспорта; Webflow-экспорт (фаза 10) берёт готовый файл;
проверка «файл соответствует исходнику» — повторный прогон инструмента с тем же хэшем.
**Б. Нет, генерировать при сборке** — один источник правды, но любой шаг после требует запуска инструмента.
