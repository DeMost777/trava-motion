# План 2.4 — инструмент подготовки SVG

**Статус:** ✅ утверждён и выполнен 2026-10-07 → [отчёт](../audits/2.4-queue-manager-prepared.md) · **Задача:** 2.4 · **Правила:** [ADR 0014](../decisions/0014-svg-preparation-rules.md),
[svg-prep-rules.md](../svg-prep-rules.md)
**Готово, когда** (из бэклога): результат визуально идентичен эталону, анимируемые элементы адресуемы.

## Что делает инструмент
`node tools/prepare-svg.mjs <raw.svg> <out.svg> --name queue-manager --expect impulse=24,hub=1,gear=1` (`--expect` добавлен при проверке, см. отчёт)

Вход — сырой экспорт `animations/queue-manager/source/figma-export.svg` (не меняется).
Выход — `animations/queue-manager/illustration.svg` (имя предварительное, стандарт пакета — 2.5).

Правки — только из раздела 2 правил, точечно по тексту файла, всё остальное остаётся байт в байт:
1. `id="m-impulse"`, `m-impulse_2` … → `data-m="impulse"`; так же `hub`, `gear`.
2. Остальные id слоёв (`Vector 137`, `Icon: user` …) удаляются. Id внутри `<defs>` (`paint…`, `filter…`, `clip…`)
   остаются — на них ссылаются фигуры.
3. У корня `<svg>`: убрать `width`/`height`, оставить `viewBox`; добавить `data-trava-animation="queue-manager"`,
   `aria-hidden="true"`, `focusable="false"`.
4. Переносы строк **оставляем** — так видно разницу между версиями в git (экономия была бы ~3 КБ).

Без внешних зависимостей (только Node), как `qa/svg-report.mjs`. Геометрию, цвета, фильтры, порядок слоёв не трогает.

**Где лежит:** новая папка `tools/` — инструменты разработки, на сайт не попадают. Альтернатива — `qa/`, но там
проверки, а не сборка. Рекомендую `tools/`.

## Проверки (встроены в инструмент, при провале — ошибка и файл не пишется)
1. **Пиксель в пиксель с сырым экспортом:** подготовленный и сырой SVG рендерятся в Chromium 480×459 — разница 0.
   Это строже, чем «не хуже эталона»: подготовка не должна менять ни одного пикселя.
2. **Против эталона Figma** (`figma-reference@1x.png`): цифры записываются в отчёт (сейчас 2.7 / 0.58 %).
3. **Роли:** `data-m` — 24 `impulse`, 1 `hub`, 1 `gear`, столько же, сколько `m-*` в исходнике.
   В браузере `querySelectorAll('[data-m="impulse"]')` находит 24 — элементы адресуемы.
4. **Ссылки целы:** каждая `url(#…)` указывает на существующий id; вне `<defs>` id не осталось.
5. `qa/svg-report.mjs`: предупреждений нет, чужих цветов нет.
6. **Повторяемость:** повторный запуск на том же входе даёт тот же файл (одинаковый хэш).

Проверки 1–3 используют Playwright (как `qa/svg-compare.mjs`); без него инструмент делает файл и
предупреждает, что визуальная проверка пропущена.

## Как проверю сам инструмент
- Прогон на Queue Manager → все 6 проверок зелёные, вывод приложу.
- **Нарочно сломанные входы** — инструмент должен остановиться с понятной ошибкой:
  а) удалён один `m-impulse`; б) возвращена тень на фрейм; в) битая ссылка `url(#…)`.
