# 3.2 — spec Fare Optimizer «на бумаге»: проверка формата

**Дата:** 2026-10-07 · **Формат:** [docs/motion-spec.md](../motion-spec.md) (ADR 0016) · **Иллюстрация:** рабочая копия `761:9491`

**Это не сценарий для утверждения.** Брифа и сценария Fare Optimizer ещё нет (фаза 11). Сцены ниже — правдоподобная
история по аудиту 1.1 и макету, нужная только чтобы проверить: выражает ли формат data-viz без костылей.

## Что в макете
График цены (линия из нескольких отрезков: зелёные — цена падает, красные — растёт), подписи осей «Price» и «Timeline»,
5 точек на линии с бейджами (Booking, Re-book ×3, Departure), панель уведомлений с тремя строками «Saved 80€ / 120€ / 160€».
Слои пока без ролей `m-*` (весь фрейм — экземпляр компонента «Optimization», см. аудит 1.1).

## Spec (черновик, EN)
```yaml
animation: fare-optimizer
story: >
  Trava watches the fare after booking; every time the price drops it re-books,
  and the savings add up in the notifications.

layers:                      # roles to be named in Figma (task 1.6 rules)
  price-line: 4              # line segments, left to right — exact count to confirm when naming layers (5 vectors in the frame, some may be axes)
  point: 5                   # markers on the line
  badge: 5                   # Booking, Re-book ×3, Departure
  axis-label: 2              # "Price", "Timeline"
  notification: 1            # panel
  saving: 3                  # "Saved 80€ / 120€ / 160€"

order:                       # NEW: how same-role layers are numbered
  price-line: by-x
  point: by-x
  badge: by-x
  saving: by-y

trigger: { when: card-active, threshold: motion.trigger.threshold, delay: motion.trigger.delay, replay: on-every-activation }
loop: { mode: once }         # data-viz tells one story and stops (principles §6)
staticState: design

scenes:
  - id: chart
    intent: The price line draws itself from booking to departure.
    primitive: drawLine
    targets: price-line
    from: hidden             # NEW: first frame is not the design for appear scenes
    params: { sequence: in-order, duration: motion.duration.long, ease: motion.ease.draw }

  - id: markers
    intent: Each point and its badge appear the moment the line reaches them.
    primitive: staggerReveal
    targets: [point, badge]
    from: hidden
    each: point              # NEW: one reveal per point, badge with the same index goes with it
    starts: when chart reaches point[i]     # NEW: indexed sync to another scene's progress
    params: { distance: motion.distance.enter, duration: motion.duration.short, ease: motion.ease.enter }

  - id: savings
    intent: >
      Each re-book adds a line to the notifications: Saved 80€, then 120€, then 160€.
    primitive: listStagger
    targets: [notification, saving]
    from: hidden
    each: saving
    starts: with markers for point[1..3]    # the three Re-book points pair with saving[0..2]
    params: { distance: motion.distance.enter, duration: motion.duration.short, ease: motion.ease.enter }

interrupt: jump-to-design
reducedMotion: static
mobile: { same: true }
```

## Результат проверки
**Формат выразил историю.** Сцены, `intent`, primitives, роли, токены, `loop: once` легли без изменений. Костылей нет,
но понадобились **три маленьких дополнения**, которых не было в Queue Manager:

| # | Чего не хватило | Почему | Предложение |
|---|---|---|---|
| 1 | Порядок одинаковых слоёв | «точка 2», «вторая экономия» — нужен номер; в Queue Manager все импульсы равны | поле `order: { role: by-x \| by-y \| document }` и ссылки `role[i]` |
| 2 | «Для каждого» и связь по номеру | точка i появляется, когда линия дошла до точки i; экономия j — вместе с Re-book j | в сцене `each: <role>` и `starts: when <scene> reaches <role>[i]` |
| 3 | Начальное состояние сцены | у появления первый кадр — пусто, у Queue Manager — макет | в сцене `from: hidden \| design` (по умолчанию `design`) |

Валидатор (3.3) сможет проверить все три: роли и их число, корректность индексов, что сцены с `from: hidden` в конце
приходят к макету.

## Вопросы на будущее (фаза 11, не к формату)
1. «Колокольчик» в прототипе звенит (покачивание) — это не противоречит ли §1 (без отскоков)? Решим в сценарии.
2. «Saved 80€…» — живой текст. Считать ли числа (счётчик) или показывать готовыми? Живой текст — риск экспорта (аудит 1.1).
3. Именование слоёв в экземпляре компонента «Optimization» — переопределения или detach в рабочей копии.
