# Правила подготовки SVG (задача 2.3)

**Статус:** ✋ черновик, ждёт утверждения · **Основание:** [отчёт 2.1](audits/2.1-queue-manager-export.md),
[отчёт 2.2](audits/2.2-queue-manager-browser-check.md) · **Применяет:** инструмент 2.4

Подготовка превращает сырой экспорт Figma (`source/figma-export.svg`) в SVG для анимации. Исходник не трогаем,
результат — отдельный файл. Главный принцип: **Figma — источник истины, подготовка не меняет внешний вид.**

## 1. Что нельзя менять (видимое)
1. Геометрию: пути, размеры, координаты, скругления. Никаких «оптимизаций» путей и округления чисел.
2. Цвета, градиенты, прозрачность — все значения как в экспорте (они уже сверены с токенами, 2.1).
3. Порядок слоёв (от него зависит «уход импульса под аватар»).
4. Тени и фильтры статичных элементов (аватары, карточка, gear) — в 2.2 они отображаются верно и не тормозят.
5. `viewBox` — система координат, в которой работает анимация.

## 2. Что можно менять (невидимое, техническое)
1. **Убрать лишние id** — имена слоёв Figma (`Vector 137`, `Icon: user`, `Content`). Оставить служебные id из
   `<defs>` (`paint…`, `filter…`, `clip…`): они содержат id узла Figma и уникальны.
2. **Пометить анимируемые слои** (см. решение 2 ниже).
3. **Убрать фиксированные `width`/`height`** у корневого `<svg>`, оставить `viewBox` — размер задаёт контейнер Webflow
   (иллюстрация адаптивная, storyboard Queue Manager, открытый вопрос 1).
4. **Добавить на корень** `data-trava-animation="<name>"` — по нему runtime находит иллюстрацию (фаза 6).
5. **Доступность:** иллюстрация декоративная — смысл карточки передаёт текст рядом → `aria-hidden="true"`
   и `focusable="false"` на корне.
6. **Пробелы и переносы строк** между тегами можно убрать. Числа и пути — нет (п. 1.1).

## 3. Проверка результата (обязательна)
- Попиксельное сравнение с эталоном Figma (`qa/svg-compare.mjs`): подготовленный SVG не должен отличаться от
  сырого больше, чем сырой от эталона. Порог зафиксируем в 2.4 на реальных цифрах.
- Все слои `m-*` на месте, количество совпадает с исходником (`qa/svg-report.mjs`).
- Цвета — только из токенов (`qa/svg-report.mjs`, позже 9.4).

## 4. Решения для команды ✋

### Решение 1. Внутренняя тень на всём фрейме (главная проблема 2.2)
Тень на корневом фрейме экспортируется неверно (в браузере затемняет всё) и роняет анимацию до ~7 кадров/с.

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **А. Исправить в Figma** ✔ рекомендую | дизайнер убирает тень с фрейма и делает тот же ободок эффектом, который экспортируется честно: внутренняя тень на самом круге `Ellipse 74` или дополнительная точка в его радиальном градиенте | Figma остаётся источником истины; экспорт сразу верный; подготовка не «дорисовывает»; правило «эффекты на фрейме запрещены» пригодится для всех 8 иллюстраций | нужна правка дизайнера (в рабочей копии) |
| Б. Убрать тень при подготовке, ободок дорисовать | инструмент 2.4 удаляет фильтр и добавляет кольцо-градиент | не нужна Figma | **проверено: ручной подбор дал разницу 22–25 против 8 без тени** — ободок «на глаз» хуже, чем ничего; подготовка начинает менять дизайн |
| В. Убрать тень и принять разницу | просто удалить фильтр | быстро, 60 кадров/с | теряется тёмный ободок по краю круга — видимое отличие от макета |

Дополнительно предлагаю **правило для дизайна:** у фрейма иллюстрации не должно быть эффектов (теней, blur);
`qa/svg-report.mjs` будет предупреждать о фильтре на корне.

### Решение 2. Как помечать анимируемые слои
Id `m-impulse`, `m-hub` совпадут, если на странице две иллюстрации (`m-impulse` есть и в Client interaction).

| Вариант | Пример | |
|---|---|---|
| **А. Атрибут роли вместо id** ✔ рекомендую | `<rect data-m="impulse">`; id удаляются | не конфликтует между иллюстрациями; runtime ищет внутри своей иллюстрации |
| Б. Префикс id | `id="qm-impulse-3"` | уникально, но длиннее, и каждый раз нужен префикс |

### Решение 3. Трансформы на импульсах (14 из 24 повёрнуты или отражены)

| Вариант | Как | |
|---|---|---|
| **А. Не трогать, учитывать в коде** ✔ рекомендую | runtime берёт направление движения из фактической геометрии на экране | геометрия не меняется — нет риска испортить градиенты |
| Б. «Запечь» трансформ в координаты | инструмент пересчитывает `x/y/width` и градиент | проще код анимации, но правка геометрии и градиентов — риск визуальных ошибок |

### Решение 4. Эталон для проверки
Сейчас эталон — WebP с потерями (чат пересжимает вложения). Для порога в 2.4 нужен эталон без потерь.
- **А. ✔ рекомендую:** PNG 2x из Figma в архиве `.zip` (SVG дошёл без изменений, архив, скорее всего, тоже дойдёт как есть — проверю хэшем) или через репозиторий.
- Б. Оставить WebP и смириться с шумом в сравнении (порог придётся ставить грубее).
