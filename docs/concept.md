# Концепция

> Сжатая версия исходного брифа. Если она расходится с брифом, прав бриф.

## Цель
Создать не набор отдельных анимаций, а **среду производства** анимаций: берём утверждённую
иллюстрацию из Figma, описываем словами движение и получаем адаптивную анимацию, проверенную
и готовую для Webflow. Каждая следующая иллюстрация собирается из уже решённых частей.

## Контекст
На сайте есть продуктовые карточки (Queue Manager, Ticketing, Quality Control, Schedule Changes,
Client Interaction, Virtual Payments, Fare Optimizer, Unused Tickets). Анимируется **только
иллюстрация справа**. Текст, навигация и фон карточки не анимируются. У каждой иллюстрации своя
маленькая история, но элементы повторяются: появление объектов, отрисовка линий, движение по path,
графики, уведомления, подсветка центрального элемента, pulse, stagger.

## Фундаментальные части
1. **Figma** — source of truth внешнего вида.
2. **SVG** — исходник для анимации: независимые элементы, геометрия как в Figma.
3. **Motion Specification** — структурированное описание поведения между словами и кодом.
4. **Motion Tokens + Primitives** — единый motion language (тайминги, easing, повторяемые движения).
5. **GSAP** — движок анимации. V1: SVG + GSAP + JavaScript, Lottie/Rive позже при необходимости ([ADR 0004](decisions/0004-gsap-official-skills.md)).
6. **Orchestrator + Skills** — AI проводит задачу по pipeline, знания лежат в Git.
7. **GitHub** — knowledge base, библиотека анимаций и рабочее пространство AI.
8. **Preview + QA** — качество проверяется до Webflow.
9. **Webflow** — только конечная точка доставки.

## Ключевые принципы
- Мы анимируем дизайн, а не воспроизводим его.
- Если Figma изменилась, меняем SVG, а не переписываем систему.
- Сначала ищем существующий primitive, новое пишем только если ничего не подходит.
- Spec отделяет идею движения от реализации.
- Адаптивность: SVG масштабируется как единый canvas, движение задаётся внутри SVG, а не в координатах экрана.
- Accessibility: при `prefers-reduced-motion` иллюстрация полностью читаема.
- Задача не готова сразу после генерации кода. Готова после проверки.
- Простая архитектура AI: Orchestrator → Builder → Skills. QA-агент появится, только если понадобится.

## POC
- **Queue Manager** — network-style: nodes, connections, центральный node, stagger, highlight.
- **Fare Optimizer** — data-viz style: график, маркеры, подписи, уведомления.

## Критерий успеха V1
Работает pipeline: SVG → spec → анимация → preview (desktop/tablet/mobile) → QA → Webflow-ready
output. Для третьей иллюстрации не нужно заново решать, где хранить код, как запускать по скроллу,
как делать responsive, какие easing брать, как называть элементы и как вставлять в Webflow.
