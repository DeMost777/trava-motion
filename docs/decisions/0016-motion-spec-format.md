# 0016. Формат Motion Specification: сцены и приёмы движения

- **Статус:** утверждено (формат); spec Queue Manager — на утверждении
- **Дата:** 2026-10-07
- **Кто утвердил:** команда Trava (в чате)
- **Задача бэклога:** 3.1

## Контекст
Нужен формат `motion.yaml`, в котором человек узнаёт свой бриф, агент однозначно понимает, что делать,
а валидатор (3.3) может проверить роли и значения.

## Варианты
[docs/plans/3.1-spec-format.md](../plans/3.1-spec-format.md): А — сцены и приёмы (primitives); Б — таймлайн, почти GSAP;
В — только текст сценария и таблица темпа.

## Решение
**А.** Spec описывает сцены: `intent` (что видит зритель), `primitive`, `targets` (роли из `figma.json`), `params`
(токены или `tempo.*` — утверждённый темп иллюстрации). Описание полей — [docs/motion-spec.md](../motion-spec.md).

## Последствия
- Словарь primitives утверждается в 5.1; названия в spec до этого — черновые (`impulseFlow`, `hubAccent`).
- Валидатор 3.3 проверяет роли, ссылки на токены и `tempo`, основания для бесконечного цикла.
- Проверка формата на втором кейсе — Fare Optimizer на бумаге (3.2).
