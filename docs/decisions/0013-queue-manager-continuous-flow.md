# 0013. Queue Manager: непрерывный поток импульсов вместо волн

- **Статус:** утверждено
- **Дата:** 2026-10-06
- **Кто утвердил:** команда Trava (значения выбраны на стенде)
- **Задача бэклога:** 1.10 (поправка сценария), Q23
- **Заменяет:** сцены 2–4 [ADR 0008](0008-queue-manager-storyboard.md)

## Контекст
По ADR 0008 импульсы шли волнами: появился → прошёл отрезок → пропал → пауза → следующая волна.
Команда уточнила смысл: «много информации идёт в одну точку», поэтому импульсы должны идти
непрерывно, один за другим.

## Варианты
- Плотность: 1 импульс на отрезке / 2–3 одновременно.
- Gear: периодическая реакция / постоянное вращение / статичен.
- Старт: поток заполняет сеть от краёв / уже идёт по всем линиям.
- Движение импульса: равномерно / ease `standard`.

## Решение
Непрерывный поток к центру по всем 24 линиям (выбрано на стенде `playground/motion/index.html`, режим «Поток»):

| Параметр | Значение |
|---|---|
| время прохода одного отрезка | 1.2 с |
| импульсов на отрезке | 1: следующий выходит из-под аватара через 1.2 с после предыдущего |
| движение импульса | равномерное, новый токен `motion.ease.flow` (GSAP `none`) |
| старт | первый кадр = макет; импульсы из макета продолжают путь, новые заполняют сеть от краёв, поток доходит до карточки за ≈3.4 с |
| gear | каждые 3 с поворот 360° + zoom до 1.2 за 1.3 с, без отскока; первая реакция — когда поток дошёл до карточки |

Перед прохождением выбор плотности на словах был «2–3 импульса», после просмотра стенда команда выбрала 1.

## Последствия
- Паузы, где кадр = макет, больше нет. Кадр = макет остаётся в первом кадре, при reduced motion, при ошибке
  и при прерывании (мгновенный переход в состояние макета).
- Цикл остаётся смысловым исключением по [ADR 0007](0007-meaningful-loop-exception.md): поток идёт, пока карточка
  активна и видна; вне экрана — пауза.
- В `tokens/motion.tokens.json` добавлен `motion.ease.flow`.
- Сценарий обновлён: [storyboard.md](../../animations/queue-manager/storyboard.md).
