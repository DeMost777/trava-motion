# Client Interaction — сценарий (черновик, ✋ ждёт утверждения)

**Смысл:** пять сервисов → одна система. Движение: [бриф](brief.md). Принципы: `motion/principles.md` (без отскоков, кадр 0 = дизайн, reduced motion = макет).

  (слева направо у левых, справа налево у правых и у верхнего/нижнего правее/левее центра).

## Сцены (непрерывно, пока карточка видна и активна)
1. **Фон.** 9 штрихов бесконечно идут к центру по своим линиям, обрезаясь по линии; медленнее основного потока и не синхронно (фаза у каждого своя). Кадр 0 = макет, штрихи продолжают с места, где нарисованы.
2. **Поток сервисов (основная сцена).** Сервисы по очереди «отдают импульс»: сервис слегка пульсирует (масштаб 1 → 1.08 → 1), из-под него выходит штрих и идёт по своему пунктиру,
   на повороте огибает угол, на входе в монитор исчезает под его карточкой. Порядок по часовой стрелке от Email: Email → SMS → Web → сеть → HTTP, шаг 0.7 с, раунд 3.5 с, дальше по кругу без паузы.
3. **Реакция монитора.** Когда штрих входит в монитор, глиф внутри карточки пульсирует (масштаб 1 → 1.2 → 1 без отскока; карточка неподвижна), как у gear в Queue Manager, но без поворота.

## Утверждено 2026-10-07 ([ADR 0019](../../docs/decisions/0019-client-interaction-scenario.md))
Штрихи потока — копии `m-impulse`, создаёт код (в статике дизайн без изменений); монитор: zoom глифа `m-core` с небольшим bounce без вращения («наполнилась»);
сервисы `m-node`: пульсация 1 → 1.08 → 1; порядок Email → SMS → Web → сеть → HTTP, шаг 0.7 с, раунд 3.5 с, скорость как в Queue Manager; фон — 9 штрихов к центру, непрерывно.
